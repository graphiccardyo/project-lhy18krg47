# rl/ — 실기 SAC 학습기 (목표 7)

PC(Python)가 정책을 계산해 결정 샘플마다 `A <du>`(PWM 증분)를 보내고, 보드(`AEROPEND_RL 1.0`)는 실행·안전·PID 복귀를 맡습니다. 프로토콜은 [docs/RL_PROTOCOL.md](../docs/RL_PROTOCOL.md)입니다.

## 구조

| 파일 | 내용 |
|---|---|
| `config.py` | 모든 숫자(플랜트·PID·LIM·RL·SAFE·에피소드·보상·휴식·SAC·정지 조건). JSON 읽기/쓰기. `[재식별]` 표시는 플랜트를 다시 식별하면 바꿀 값 |
| `link.py` | 연결: `SerialLink`(pyserial 또는 가짜 포트, 읽기 스레드, 0.25 s PING, 감시견), `VirtualLink`(가상시간). D 줄을 받은 읽기 스레드에서 바로 `A`를 보내는 `fast_path` |
| `plant.py`, `fake_board.py` | 11-15 재식별 모델 플랜트(정적 지도 + 1차 지연 + 느린 경로 + 공진 + 지연 + 마찰 + 정지 오프셋 + 선택: 케이블 충격, 도메인 랜덤화)와 RL 펌웨어를 줄 단위로 흉내 내는 가짜 보드(`FakePort` = 실시간) |
| `env.py` | D 줄 → 관측·행동·보상·전이 |
| `sac.py` | PyTorch SAC(쌍둥이 Q, 자동 엔트로피, 버퍼, 체크포인트) + numpy 추론 |
| `trainer.py` | 상태 기계 스레드: 연결·설정 → PID 기준선 → [휴식] → [평가] → 복귀 → 에피소드 → 갱신. `status()`/`command()` (모듈 docstring에 정확한 형식) |
| `record.py` | 실행 폴더 기록 |
| `train.py` | CLI |
| `play.py` | 학습 없이 저장된 정책 시험 CLI (`Trainer`의 연결·복귀·에피소드 코드를 그대로 씀) |
| `fork.py` | 실행 분기: 정책 스냅샷 시점에서 새 실행 폴더(버퍼 자르기·오염 전이 제외·크리틱 재적응) → `--resume` |
| `imu_check.py` | 정지 상태 IMU 점검(모터 안 돌림, EEPROM 안 바꿈): 잔여 자이로 편향·θ 표류율·θ − θacc 를 Madgwick 보정 한계(β)와 비교 |
| `bench_test.py` | 프로토콜 적합성 시험 (BENCH 1 전용) + 왕복 지연 측정 |
| `selftest.py` | 하드웨어 없는 자체 시험 |

## 실행

Python은 `.venv\Scripts\python.exe`입니다(numpy, scipy, pyserial, torch CPU).

```powershell
.venv\Scripts\python.exe -m rl.selftest                    # 하드웨어 없이 전부 (몇 분, --quick 은 학습 시험 생략)
.venv\Scripts\python.exe -m rl.bench_test --fake --fast    # 가짜 보드로 프로토콜 시험
.venv\Scripts\python.exe -m rl.bench_test --port COM4      # 실제 보드, BENCH 1 에서만 (모터 안 돎)
.venv\Scripts\python.exe -m rl.train --fake --fast --episodes 200   # 가짜 보드 가상시간 학습
.venv\Scripts\python.exe -m rl.train --port COM4 --hours 2          # 실기 학습 (모터가 돕니다)
.venv\Scripts\python.exe -m rl.train --port COM4 --resume data\20261114_rl1   # 이어 하기
```

## 스냅샷 (정책 시점별 저장)

`checkpoint/`(이어 하기용, 덮어씀)와 별도로 `checkpoints/<이름>/`에 정책만 남깁니다. 폴더마다 `actor.pt`(액터 가중치, 약 22 KB — 리플레이 버퍼·크리틱·옵티마이저 없음)와 `meta.json`(종류, 학습 에피소드, 결정 수, 갱신 수, 그 정책의 평가 RMS, 저장 시점의 최근 평가 RMS, 시각)입니다.

| 이름 | 언제 |
|---|---|
| `ep00050`, `ep00100`, … | 학습 `run.snapshot_every`(기본 50, 0 = 끔) 에피소드마다 |
| `best` | 평가 라운드 평균 RMS가 지금까지의 `best`보다 작을 때 (덮어씀). 이 기능 전에 시작한 실행을 이어 하면 이어 한 뒤 첫 평가가 처음 `best`가 됩니다 |
| `manual_<에피소드>_<HHMMSS>` | 대시보드 **지금 저장**, 표준입력 `n`, `command('snapshot')` |

- 수동 저장은 제어 루프를 방해하지 않게 다음 에피소드 경계(또는 휴식 중)에 처리하고, 대기·일시정지 중이면 바로 저장합니다.
- **지금 평가**(표준입력 `e`, `command('eval')`)는 다음 에피소드 경계에서 평가 라운드를 한 번 더 돌립니다. 정기 평가와 똑같이 기록하고(`eval_scores`에 `manual: true`), 정기 평가 일정은 바뀌지 않습니다.
- 옛 `config.json`(이 키 없음)과 옛 `checkpoint/`도 그대로 `--resume` 됩니다. 단, 새 코드로 이어 하면 `config.json`에 `snapshot_every`가 추가되므로 그 실행을 다시 옛 코드로 열 수는 없습니다.

## 정책 시험 (`rl.play`, 학습 없음)

저장된 정책이 기준 각도를 얼마나 잘 유지·추종하는지 봅니다. 학습기가 포트를 쓰고 있지 않을 때 실행하세요. 정책은 결정적(평균 행동), 갱신·버퍼 없음. 설정은 그 실행 폴더의 `config.json`(PID·LIM·RL·SAFE 포함)을 그대로 보냅니다.

```powershell
# 최신 체크포인트(checkpoint/)로 25° 유지 20 s  — 모터가 돕니다
.venv\Scripts\python.exe -m rl.play --port COM4 --ckpt data\20261114_rl1 --hold 25
# best 스냅샷으로 20° → 30° → (10 s 뒤) 22°, 같은 시나리오를 보드 PID로도 돌려 비교, 2회 반복
.venv\Scripts\python.exe -m rl.play --port COM4 --ckpt data\20261114_rl1 --snapshot best --refs 20 30 22 --pid --repeat 2
# 스냅샷 폴더를 직접 / BENCH 1 드라이런(모터 안 돎) / 가짜 보드
.venv\Scripts\python.exe -m rl.play --port COM4 --ckpt data\20261114_rl1\checkpoints\ep00100 --bench
.venv\Scripts\python.exe -m rl.play --fake --fast --ckpt data\20261114_rl1 --refs 20 30 22 --pid --out $env:TEMP\play
```

- `--ckpt`: 실행 폴더(→ `checkpoint/`), 실행 폴더 + `--snapshot 이름`, 스냅샷 폴더, `checkpoint` 폴더, `.pt` 파일.
- 시나리오: `--hold θ`(= home·r1·r2 모두 θ) 또는 `--refs home r1 r2 [home r1 r2 …]`(학습기 평가와 같은 의미, r2는 에피소드 절반에서). 둘 다 없으면 설정의 평가 시나리오 3개. `--dur`(기본 20 s), `--repeat`, `--settle`(정착 구간에서 뺄 시간, 기본 3 s), `--no-plot`, `--out`.
- 절차·안전은 학습기와 같습니다: 연결·설정 → `REF home` 정착 → `RUN RL` → … → `STOP`. `EVT ABORT`·연결 오류·miss 초과·Ctrl+C 어떤 경우에도 `STOP`을 보내고 끝냅니다. `ZERO`는 보내지 않습니다. `--port`(벤치 아님)이면 시작 전에 모터가 돈다는 안내를 출력합니다.
- 출력: 표(전체 RMS, 정착 구간 평균 |e|·σ(e), 오버슈트 °/%, 평균 PWM, 정착 구간 PWM σ, miss, FALLBACK)와 `<run_dir>/play/<YYYYMMDD_HHMMSS>/`에 `episodes/*.csv`(학습기와 같은 형식, `mode=play`/`pid`), `play_log.csv`, `events.log`, `config.json`, `summary.json`, `play.png`(시나리오마다 θ·기준, PWM; `--pid`면 PID 겹침).

## 분기 (`rl.fork`, 중간 시점에서 다시)

`checkpoint/`는 덮어써서 마지막 상태만 남으므로, 실행 후반 데이터가 오염됐을 때 그 전으로 돌아가려면 정책 스냅샷에서 새 실행 폴더를 만듭니다(원본은 읽기만).

```powershell
.venv\Scripts\python.exe -m rl.fork data\20261115_rl3 --snapshot ep00050          # → data\<오늘>_rl<다음>
.venv\Scripts\python.exe -m rl.train --port COM4 --resume data\20261115_rl4
```

- 액터 = 스냅샷(α 포함), 버퍼 = 그 스냅샷까지 쌓인 전이(train_log의 `buffer` 열로 자름) 중 θ − θacc 10 s 이동평균이 `--max-gap`(3°, 학습기 감시와 같은 기준)을 넘는 결정 샘플의 전이를 뺀 것.
- 크리틱은 스냅샷에 없어서 원본 마지막 체크포인트의 크리틱에서 시작해, 거른 버퍼로 크리틱만 `--critic-steps`(10000, 약 10 s) 번 갱신해 스냅샷 액터에 다시 맞춥니다.
- 진행 상태(학습 에피소드·결정 수·평가 점수·학습 곡선·CSV 번호·경과 시간)는 그 시점 값, 그 뒤의 평가·기준선은 버림. PID 기준선은 비워서 이어 하기 시작 때 다시 잽니다(`--keep-baseline`이면 유지). 설정은 원본 config.json + `--config`(바꿀 항목만).
- `fork.json`에 출처·제외 수·크리틱 손실, `train_log.csv`에 그 시점까지의 줄(att_gap 다시 계산), 그 시점 이전 스냅샷 복사. 에피소드 CSV는 원본에만 있습니다.
- 11-15: `20261115_rl3`(진동으로 자이로 편향, 02:15부터 간극 2–4°, 재개 뒤 10–29°) → `20261115_rl4` = ep00050(02:46) 시점, 버퍼 50154/61938(11784개 제외).
- **보상 재라벨**: `--config`로 보상 관련 키(`fork.REWARD_KEYS`: err_scale, w_abs, w_du, w_ddu, w_fine, w_omega …, reward_scale, act_pow)를 바꾸면 남긴 전이의 보상을 새 식으로 다시 계산합니다(`env.reward_from_obs`: 다음 관측 o2의 오차·각속도와 정책 행동, 직전 행동 o[5]). 먼저 원본 식으로 다시 계산해 저장값과 비교한 오차를 보고합니다(k<sub>I</sub> > 0 실행은 정확히 일치, rl8 168,831개 최대 7×10⁻⁸). 종단 전이는 reward_scale 비율만, 관측 정의 키(th_scale, w_scale, obs_* …)가 바뀌면 거부. 재라벨하면 크리틱 재적응 기본 20000회. `--relabel no`로 끌 수 있습니다.
- 11-15 오후: `20261115_rl8` best(ep 120) → **`20261115_rl9`**, `{"env": {"w_omega": 1.0, "w_ddu": 0.3}}`로 재라벨(평균 보상 −0.0848 → −0.0925), 버퍼 155,844개 전부, 크리틱 20000회, PID 기준선은 이어 하기 시작 때 다시 잽니다. config.json의 가짜 보드 플랜트는 11-15 모델로 맞춰 둠(실기에는 영향 없음).

- `--dashboard 8780`으로 포트를 바꾸고, `--no-dashboard`로 끕니다. 포트를 못 열면 경고만 찍고 학습은 계속합니다.
- 서버는 `127.0.0.1`에만 바인드합니다. 명령 API(`POST /api/command`)는 JSON 본문만, 로컬 호스트 이름(`127.0.0.1`·`localhost`·`[::1]`)만 받습니다.
- 정지 버튼은 확인창을 한 번 띄웁니다. 학습기가 죽으면 화면에 "학습기와 연결 끊김"이 뜹니다.

- **지금 저장**·**지금 평가** 버튼과 스냅샷 표(이름, 에피소드, 평가 RMS, 시각; `best` 굵게)가 있습니다.

`train` 옵션: `--config cfg.json`(바꿀 항목만 적은 JSON), `--hours`, `--episodes`, `--bench`(BENCH 1 드라이런), 가짜 보드 전용 `--randomize`(도메인 랜덤화), `--shock 0.1`(케이블 충격/s), `--latency-ms 7 9`. 실행 중 표준입력 `p`/`r`/`q`/`s`/`n`/`e` = 일시정지/재개/정지/상태/스냅샷/지금 평가.

## 설정 요점 (기본값)

- 보드: `RL 2 2 10 40 255`(결정 20 ms, 적용 지연 2샘플 — 실측 왕복 7–9 ms라 lag 1은 누락), `SAFE −10° 70° 600 °/s`, `LIM 255 100°`(PID 시험과 같은 상한), PID 0.9/7/0.02 ff 140 umin 40(노치 끔). 학습기가 시작할 때 전부 명시적으로 보냅니다.
- 에피소드 20 s, 기준 15–30°에서 무작위(home도 무작위), 중간(35–65%)에 `REF`로 한 번 스텝 → 구간 7–13 s. 평가 시나리오 3개(20→30→22, 30→18→28, 25→30→16)는 PID 기준선과 같고 스텝은 10 s에서. 10 s(구간 3.5–6.5 s)일 때는 샘플의 절반이 과도 구간이라 보상이 과도 응답에 치우쳤고 느린 경로(Tc 6 s)가 담기지 않았습니다. 대신 같은 시간에 스텝 수는 절반입니다.
- 구간 지표(`trainer.steady_metrics`, 창 = 각 구간 마지막 `run.ss_win_s` 3 s):
  - 편향 `ss_bias` = 창 평균 e의 크기(오래 남는 오프셋), 리플 `ss_ripple` = 창 안 σ(e)(공진·케이블 울림·잡음). 예전 `ss_abs`(평균 |e|)는 둘이 섞인 값이라 남겨만 둡니다.
  - 정착 시간 `settle_s` = 기준 변경 뒤 |e|의 0.2 s 이동평균이 ±`run.settle_band_deg`(0.5°) 안에 끝까지 머물기 시작한 시각. 끝까지 못 들어오면 구간 길이(검열값).
  - 오버슈트 `os_pct` = 1° 이상 기준 변경마다 새 기준을 넘어간 최대량 / 스텝 크기.
  - 보고서에서 "정상상태 오차"를 말하려면 이 창(스텝 뒤 4–10 s)보다 긴 유지 시험(`rl.play --refs … --dur 30 --pid`)이 맞습니다.
- PID 기준선: 시작 때 + 정기 평가 `run.baseline_every`(5)회마다 다시 잽니다. 세션 중 플랜트가 흘러가기 때문입니다(rl1에서 30° 유지 PWM이 188 → 192–197).
- 관측 8차원: `[e/10, (θ−25)/10, ω_f/100, Δθ, (u−125)/85, a_prev, ē/2, tanh(e/0.5)]`. 마지막 미세 오차 채널(`env.obs_efine`)은 0.5° 오차가 첫 항으로는 0.05밖에 안 돼서 넣었습니다.
- 보상: `−min((e/2)², 16) − |e|/2 − 2·(1 − exp(−(e/0.5)²)) − 0.05·a² − 0.1·(a − a_prev)²`, 전체 ×0.03. 셋째 항(정밀 항, `env.w_fine`/`fine_scale`)은 0.2–1°에서 기울기가 큽니다. 이 항 덕분에 8° 대 0.5° 벌점 비가 64에서 14로 줄어, 작은 정상상태 오차가 과도 응답 벌점에 묻히지 않습니다. `w_ddu`를 0.02에서 0.1로 올린 것은 정착 구간의 du 떨림 때문입니다.
- **감쇠 항**(선택, 기본 꺼짐 `env.w_omega` 0): `−w_omega · exp(−(e/omega_gate)²) · min((ω_f/omega_scale)², omega_cap)`, 기본 scale 20 °/s · gate 2° · cap 4. 기준 근처에서만 각속도에 벌점을 줘 2.3–2.6 Hz 공진 리플을 줄이게 합니다(기준에서 멀면 게이트가 꺼져 상승을 늦추지 않음). rl8 30 s 유지 시험에서 오차 대부분이 이 리플이었고 PWM 변화량이 PID의 약 8배였습니다.
  - 가짜 보드(11-15 플랜트, 케이블 충격 0.05/s, 처음부터 70 ep, 2 시드) 마지막 평가 9회: 리플 σ rl8 설정 0.42° → **w_omega 1 + w_ddu 0.3: 0.28°**(상승 1.18 → 1.45 s) → w_omega 2: 0.35°(상승 2.27 s, 너무 셈). 시드 차이가 커서 참고용입니다.
  - 실기는 `20261115_rl9`(rl8 best에서 분기, w_omega 1.0, w_ddu 0.3)로 시험합니다. 새 실행 기본값은 하드웨어 결과를 본 뒤 정합니다.
- 고정 적분 보조(`env.ki_assist` k_I = 6 PWM/(°·s), 보드 PID ki와 같은 단위): 정책 증분에 `k_I·dt·e`를 더해 보냅니다. 전체 제어기 = 고정 적분 + RL 잔차 정책(잔차 RL)입니다.
  - 정책 출력 0의 의미가 "PWM 유지"에서 "오차 적분"으로 바뀝니다. rl3에서는 모터·드라이버 과열로 이득이 변하자 정책이 e ≈ 1.4°에서 du ≈ 0으로 멈춰 편향이 남았습니다.
  - 엄격한 역할 분리는 아닙니다. 큰 오차(과도)에서는 정책 증분(±10/결정)이 순간 적분 증분(k_I 6, 10°에서 1.2/결정)보다 커서 정책이 지배하고, 정상상태 근처에서는 행동 벌점 때문에 정책 출력이 작아 적분이 지배합니다. 정책은 이 적분 루프를 포함한 환경을 학습합니다.
  - 평형 편향은 `e* = −(정책 몫)/(k_I·dt)`입니다. 11-15 rl1(k_I 3)에서는 정책 출력 영점의 오프셋(−0.06 PWM/결정)이 적분을 상쇄해 θ가 기준보다 약 1° 낮게 머물렀습니다. 같은 오프셋이면 k_I 6에서 약 0.5°입니다.
  - k_I를 키우면 편향은 줄지만 순간 증분이 작아도 상승 동안 쌓이는 양(k_I 10, ∫e ≈ 3 °·s → 30 PWM)이 오버슈트를 만듭니다. 가짜 보드(공칭, 20 s, 2 시드 60 ep) k_I 3/6/10: 편향 0.31/0.25/0.21°, OS 7.9/5.9/13.9%, 정착 4.1/3.5/4.0 s(PID 0.19°·5.9%·2.3 s). 적분 분리(`env.ki_band_deg`, x_I에 exp(−(e/폭)²))는 OS는 줄였지만 편향 이점이 사라져 기본은 끔입니다.
  - 행동 벌점과 리플레이 행동은 정책 몫만 씁니다(적분 몫까지 벌하면 정책이 적분 움직임을 상쇄하도록 배움). 속도형이고 보드가 u를 자르므로 와인드업이 없습니다. `train_log`의 `mean_abs_di`가 결정당 적분 증분 평균입니다.
  - 평가·`rl.play`에서도 같이 동작합니다(제어기의 일부).
- 휴식: 모터 가동 누적 300 s마다 `STOP` 후 90 s. 휴식 끝에 정지 각도 |θ| ≤ 5° 확인(정지 위치가 0°로 안 돌아올 수 있어 너그럽게, `ZERO`는 절대 자동으로 보내지 않음).
- SAC: 64-64 MLP, 배치 256, γ 0.99, lr 3e-4, τ 0.005, 워밍업 2500 결정(20 s 에피소드로 약 2.5 에피소드) 무작위, 결정당 갱신 1회(에피소드 사이에 몰아서).

### 11-14 이후 기본값 변경과 옛 실행

`data/20261114_rl1`은 PWM 상한 210, 기준 15–35°(평가 25→33→16), 관측 7차원, 정밀 항 없음, `w_ddu` 0.02로 돌렸습니다. 33°에서 PWM 210에 붙어 정상상태 오차가 1–1.6° 남았고, 학습 샘플의 12%가 포화였습니다.

- 실행 폴더의 `config.json`은 설정 전체를 저장하므로 옛 실행은 옛 값 그대로 `--resume`·`rl.play` 됩니다. 새 키(`env.obs_efine`, `env.w_fine`, `env.ki_assist`, `run.baseline_every`)가 없으면 옛 동작(관측 7차원, 정밀 항 0, 적분 보조 0, 기준선 시작 때만)으로 읽습니다(`config.load_run_config`). `data/20261114_rl3`은 적분 보조 이전 설정이라 이어 하거나 시험하면 k_I = 0으로 동작합니다. `data/20261115_rl1`은 k_I 3·10 s 에피소드 설정 그대로 이어집니다(설정 파일에 값이 있음).
- 새 기본값으로 비교하려면 새 실행으로 시작하세요(관측 차원이 달라 옛 체크포인트를 이어 받을 수 없음).
- 이어 하기 때 `train_log.csv`는 기존 머리줄의 열을 그대로 씁니다(옛 실행에는 `ss_*` 열이 안 생김).

## 안전

- 모터를 돌리는 명령은 `train --port`만 보냅니다. `bench_test`는 `BENCH 1`이 확인돼야 `REF`/`RUN`/`U`를 보내고, `CFG BACKUP`으로 시작해 `CFG RESTORE`로 끝냅니다. `ZERO`·`FACTORY`·보정은 보내지 않습니다.
- 자동 일시정지(모터 `STOP`, 사람이 `resume`): `EVT ABORT`, 포트 오류·2 s 무수신, `S` 줄 overruns 급증·sat 이상·IMU 오류, 에피소드 miss > 20%, 예상치 못한 `EVT STOP`, 휴식 끝 정지 각도 이상, **자세 추정 이상**.
- 자세 추정 감시(`monitor.att_gap_*`): 모터 가동 중 θ − θacc의 10 s 이동평균이 3°를 넘으면 일시정지, 2°를 넘으면 경고(60 s에 한 번). 대시보드 카드 **자세 추정 θ − θacc**에 현재 값이 나옵니다(정상 0.3–0.9°).
  - 11-15 rl3에서 진동이 커지자 자이로가 모터 가동 중에만 편향돼(진동 정류) Madgwick β 0.004의 보정 예산(≈ 2β = 0.46 °/s, 수평 두 축 공유)을 넘었고, θ가 θacc에서 2–4° → 25–29°까지 떠내려가 `FALLBACK THETA`가 났습니다. 간극은 PWM이 높을수록 빨리 커지고(200 이상에서 +0.5 °/s), 휴식(모터 정지) 중에는 회복됩니다.
  - 기록을 같은 방식으로 재생하면 정상 실행 3개는 최대 1.8–2.7°로 한 번도 멈추지 않고, rl3은 02:15:16(간극이 커지기 시작한 때)에 멈춥니다. 2 s 창은 무작위 워밍업의 과도 지연으로 정상 실행에서도 3.7°까지 나와 쓰지 않습니다.
  - 11-15 후속: 정지 점검(`rl.imu_check`)에서 모터를 끈 채로도 진자 축 자이로 편향이 운전 온도에서 +0.57 °/s, 식은 뒤 −0.41 °/s로 약 1 °/s 흔들렸습니다(Y축도 0.9 °/s). 그래서 `CAL`(정지 보정, 따뜻할 때)을 다시 하고 β를 0.004 → 0.01로 올렸습니다(보정 예산 0.46 → 1.15 °/s). β 0.01에서 같은 −0.41 °/s 편향의 정지 간극은 60 s 동안 0.0°로 유지됩니다(β 0.004에서는 −0.8°까지 벌어짐). β는 느린 표류만 바로잡습니다. 같은 날 오후 플랜트를 다시 식별해(data/20261115_run1) 가짜 보드 기본값을 11-15 모델(공진 2.35 Hz)로 바꿨습니다. CSV 머리줄 `beta=`로 실행마다 확인할 수 있습니다. 세션 시작 전에 `rl.imu_check`(1분)를 권장합니다.
  - 멈추면 프로펠러·모터·마운트를 확인하세요. 쉬고 재개하면 간극이 줄어 있을 수 있지만 원인이 남아 있으면 다시 멈춥니다. `rl.play`에도 같이 적용됩니다. 끄려면 `monitor.att_gap_max_deg` 0.
- 자동 종료: 총 시간, 학습 에피소드 수, FALLBACK 누적. 어떤 예외로 끝나도 `STOP`과 체크포인트를 남깁니다.
- 학습기 주 스레드가 20 s 넘게 멈추면 하트비트를 끊어 보드가 1 s 뒤 스스로 정지합니다. 프로세스가 죽어도 마찬가지입니다.
- 보드 쪽 안전장치(각도 한계, `SAFE` → PID 복귀, u_lo/u_hi, du_max, 하트비트)는 PC와 무관하게 동작합니다.
